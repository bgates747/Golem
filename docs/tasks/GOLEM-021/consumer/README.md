# MOS consumer and human review

The assembly application uploads separately compiled Xtensa code after the real
ESP32 firmware boots, calls it, unloads it and saves its replies through MOS.
The complete Fab/Flexe runtime passes numeric and packed-renderer proofs in both
engines and returns to the MOS prompt. The Oryx visual fixture is staged and
stopped for the Author. This is functional emulation; physical timing,
hardware acceptance and human keyboard/visual review are separate.

## Source roles

`probe.asm` runs on the eZ80. It loads `script.bin` from SD, transmits the script's
VDU packets, patches handles returned by the loader, receives correlated replies
through the existing MOS keyboard-vector hook, and saves `results.dat`. It does
not compute the numerical answers or draw the packed image itself.

`build.py` creates that transaction script and its independent expected replies.
`assets.py` extracts a real Lode Runner HGR page from the agon-6502 snapshot;
its source identity and packing policy are recorded with the generated bytes.
The numeric source is under GOLEM-002/proof; the packed source is under
GOLEM-002/packed-mono. Compiled module packages share GOLEM-002/proof/build.
Neither module is linked into the firmware. Module operations execute as actual
Xtensa instructions through Flexe, with firmware compatibility hooks disabled.

The callback copies only ten reply bytes and turns the received packet into a
null key-up before returning to ordinary MOS handling. The foreground validates
protocol, kind, token and expected values. A successful load supplies a fresh
nonzero handle; no firmware entry address is hard-coded into the application.

## Reproduce the numeric proof

From the Golem root, after building the owned emulator and native firmware:

```bash
.venv/bin/python docs/tasks/GOLEM-002/proof/build_modules.py
.venv/bin/python docs/tasks/GOLEM-021/consumer/build.py
.venv/bin/python docs/tasks/GOLEM-021/consumer/profile.py \
  --frontend docs/tasks/GOLEM-021/emulator/build/fab-source/target/release/fab-agon-emulator \
  --firmware docs/tasks/GOLEM-002/runtime/build/firmware-src/.pio/build/esp32dev/firmware.bin \
  --elf docs/tasks/GOLEM-002/runtime/build/firmware-src/.pio/build/esp32dev/firmware.elf
.venv/bin/python docs/tasks/GOLEM-021/consumer/qualify.py --engine jit
.venv/bin/python docs/tasks/GOLEM-021/consumer/qualify.py --engine interp
```

The qualifier is headless. It removes the previous saved result, verifies the
new transcript, waits for the actual post-success MOS prompt, then closes only
its own frontend through normal cleanup. Receipts include source/runtime hashes,
observed library mappings, backend counters and elapsed execution time. It does
not ask the Author to type a command or claim a human review.

The archived numeric-v2 runs pass 44 replies / 440 saved bytes: JIT 8.795 s,
interpreter 15.723 s on the development Pi. Both saved transcripts have SHA256
`e06ad6d9fdb791dbaefc495263fa30d0ffefcc9f159c57eb7e8b1ad36e2413c9`.
Their [JIT](../evidence/numeric-jit.json) and
[interpreter](../evidence/numeric-interp.json) receipts pin the numeric-v2
firmware. The commands above select the current build, whose packed-frame
capability and native entry addresses differ; they reproduce the numeric
behavior without promising that archived transcript digest.
Those are host execution durations, excluding build/staging; they are not ESP32
performance measurements. Earlier attempts are retained with their identities.

## Packed proof and Oryx staging

Build the updated loader firmware once, compile the separately uploaded module,
and prepare the recognizable image/script:

```bash
.venv/bin/python docs/tasks/GOLEM-002/runtime/build_firmware.py
.venv/bin/python docs/tasks/GOLEM-002/proof/build_modules.py --packed
.venv/bin/python docs/tasks/GOLEM-021/consumer/assets.py
.venv/bin/python docs/tasks/GOLEM-021/consumer/build.py --packed
.venv/bin/python docs/tasks/GOLEM-021/consumer/profile.py \
  --frontend docs/tasks/GOLEM-021/emulator/build/fab-source/target/release/fab-agon-emulator \
  --firmware docs/tasks/GOLEM-002/runtime/build/firmware-src/.pio/build/esp32dev/firmware.bin \
  --elf docs/tasks/GOLEM-002/runtime/build/firmware-src/.pio/build/esp32dev/firmware.elf
bash docs/tasks/GOLEM-021/emulator/stage_oryx.sh
.venv/bin/python docs/tasks/GOLEM-021/consumer/stage_oryx.py
```

The final command transfers exact staged artifacts and readable source, checks
their identities, generates the Oryx profile, runs both engines headlessly,
retrieves results and leaves it stopped. Oryx lacks the environment checkout's
profile generator, so the bundle includes an exact canonical script snapshot
and passes it explicitly through `--setup-script`; its contents are hash-checked.
No upstream or remote environment checkout is changed.

The final fixture checks native numeric state/replacement, two six-byte resident
renderer calls, unsupported mode, a short inverted source and negative geometry.
After both geometry/source failures, every pixel in the 280x192 image and its
40-pixel black margin must still match. INFO17 records actual command-task free
stack space; the complete proof returns to MOS before the agent stops it.

## Direct profile entry

`profile.py` uses the canonical profile generator and extends its generated
wrapper with pinned firmware, diagnostic ELF and capture paths. The profile's
own executable is a real wrapper, and its hash is included with the runtime
identity. No outer environment setup or alternate raw-binary launch is needed:

```bash
cd ~/Agon/mystuff/golem/docs/tasks/GOLEM-021/.emulator
./flexe-agon-emulator
```

Run those commands on Oryx only after its staging is announced ready. The agent
does not launch the graphical review. Follow the guest's single instruction to
type `dir`, close the emulator, and tell the agent whether the display and command
worked. The agent retrieves and verifies saved results. The emulator can remain
closed. The generated launcher deletes previous saved results before every run,
so repeating the same launch command produces fresh evidence.

## Wire accounting

A direct silent vdplet RUN frame is 17 bytes. The packed fixture installs that
packet into a stock VDP buffer once, with assembly patching its runtime handle,
then calls it for six bytes. INFO queries and reply/readback traffic are proof
instrumentation. They are excluded from the production invocation count.

The native row-copy module consumes an already decoded packed buffer. Existing
compressed page/delta transport in agon-6502 can continue unchanged. A static
screen proves module loading, resident reuse and pixel correctness; it does not
claim to benchmark a running game or its compression ratio.

## Tape and wait limits

The trusted build script emits only bounded raw payloads and small transaction
metadata. The application has a fixed 4 KiB transcript and a 64 KiB script region;
the builder enforces both. Individual reply waits expire using MOS's timer.
Type 3 counts a finite number of MOS timer changes, driven by native VSync. A
stopped VSync source cannot expire that guest wait itself; automated qualification
has an independent host wall deadline. This is a test harness, not a cancellation
mechanism for arbitrary native code. Native entry points must return normally.
