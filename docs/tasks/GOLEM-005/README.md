# Terminator-free parser tranche

The maintained compiler and an experimental scalar successor share one token
reader. Existing ordinary and scalar command generation stays unchanged;
statement boundaries now follow grammar without semicolons or significant
newlines. The scalar successor remains isolated here, using GOLEM-003's backend.
Shared allocation and resident integration are the next separate increment.

## Using the parsers

```sh
make -C src
build/golemc examples/loop_golem/loop.golem /tmp/loop.bin
make -C docs/tasks/GOLEM-005
# From the project root; these are raw VDU streams, not MOS executables.
docs/tasks/GOLEM-005/build/golemc-scalar \
  docs/tasks/GOLEM-005/examples/floor.golem \
  docs/tasks/GOLEM-005/build/example -0.75
make -C docs/tasks/GOLEM-005 check
```

The first command emits main's existing raw payload. The separate scalar CLI
emits bootstrap.bin, cleanup.bin, invoke.bin, update-call.bin and interface.json.
Installation does not call the job. Initial bounds and host updates, including
binary32 rounding, retain GOLEM-003's checks. Wire sizes remain 1008 installation
bytes and 21 recurring input-update/call bytes, excluding output readback.
The manifest changes only its experimental task label to GOLEM-005.

## Migration

Remove semicolons at statement/block boundaries from maintained Golem source.
Keep semicolons inside strings/comments, and keep expression parentheses/commas.
The compiler deliberately rejects legacy semicolons; it does not strip source or
maintain a second production legacy parser. For example:

```golem
uint16 a = 1 uint16 b b = a + 2
print "foo" print "bar"
uint16 i
For i = 1 To 2
    a = a +
        i
Next i
```

Bare declarations still zero-initialize. For counters must already be declared,
and Next must repeat the same case-sensitive name. Keywords and builtins are
case-insensitive; identifiers remain case-sensitive. Main implements print of
string literals, uint16 declarations/assignment/addition and For/Next only.
This task's scalar parser still accepts exactly one bounded float32 input,
one sint16 output and one Sub job assigning sint16(floor(input)).

The shared reserved names are:

```text
print uint16 for to next float32 sint16 range sub endsub floor str
if then elseif else endif do while until loop switch case default endswitch
```

Older source using a future keyword such as If or Range as an identifier must
rename it. Reserving a name does not implement its construct. If/Do/Switch,
general calls, function parameters, string conversion and Range extensions
remain unsupported. Bounds is an unselected spelling, not a reserved keyword.
The declaration Range still describes a continuous finite numeric interval.

Numeric tokens must be complete: 1foo, 0x1, incomplete exponents and repeated
decimal points fail with line/column diagnostics. Integer conversion checks
0..65535 directly without overflow or conversion through double. Scalar decimal
conversion rejects nonfinite, overflow and double underflow to zero rather than
silently losing a nonzero literal. Finite double subnormals remain accepted;
binary32 admission checks and rounding behavior are unchanged.
Strings preserve the old decoded bytes and escape rules (\\, \", \n); // comments
and newlines retain their previous whitespace behavior.

## Evidence and limits

Host checks pass with C++17, strict warnings and address/undefined-behavior
sanitizers: 20 ordinary and 22 scalar byte-equivalence pairs, 69 rejection
checks, source spans, casing and defaults. Ten CLI rejection cases preserve
existing output. Both migrated executable examples retain their generated bytes.

`run_checks.py` obtains the exact ordinary baseline from commit
6a2017c26968be2631c955f67508d9e3ad0d16d7 and compiles it only under ignored build/.
The old scalar parser, backend, Rally oracle and historical reports are untouched.
The sanitizer suite compares complete emitted streams, not selected opcodes.
CLI checks compare all four scalar binary outputs and interface fields, check
failed compilation preserves existing output, and compare migrated maintained
examples against their actual pre-tranche source. `examples/scratch.golem`
remains a design sample containing unsupported print str(...), not a fixture.
Commands, source fingerprints and durations are recorded in host-checks.json.
The historical GOLEM-003 runner includes legacy-semicolon checks against main;
use this task's runner for the changed maintained frontend. Its original report
remains evidence for the source fingerprints and revision recorded there.

No firmware execution or deployment is claimed. The existing ordinary loop's
65535 conditional sentinel and counter-wrap concerns remain as documented in
GOLEM-004; compile-only byte parity does not qualify them. Allocation collisions
between ordinary and scalar programs remain unresolved, so their streams must
not be combined. Scalar job reentrancy, host-bound obligations and non-atomic
multi-file publication remain GOLEM-003's existing limitations.
