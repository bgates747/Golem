# SYN-001 — Storage, indexed access and checked-copy examples

The shared examples now consolidate GOLEM-010's reviewed direction using ordinary
assignments and parenthesized indexing. Each sample has typed declarations and
explicit initial state or an assembly installation precondition. File mappings
stay outside resident source. No compiler feature was implemented; stop for
Author review before the final REV-001 synthesis.

Open [examples.golem](/Agon/mystuff/golem/docs/tasks/GOLEM-003/examples/examples.golem).
Each EX block is independent. Repeated type/variable/entry names are intentional;
the whole review file is not one compilable program.

Payload sizes above exclude program code, scratch, VDP command headers and
transport framing. File names describe PC build inputs, not strings embedded in
resident jobs. Zero-filled payloads can be generated by the build; no runtime
loose-file lookup is required. Assembly installs scalar/record initializer bytes
from compiler output as well as externally configured asset payloads.

## Compiler-to-assembly boundary

The compiler assigns physical buffer IDs/offsets and emits data, command buffers,
entry locations and ownership information. Assembly performs installation,
updates, invocation, pacing and cleanup. Existing binaries/interface.json are
the current output; generated assembly equates, labeled byte definitions and
lengths are the intended additional output mode and are not yet implemented.
The build should drive that output and any AGNB writer from the same layout.

AGNB is a bulk-loading option for the assembly application. Existing AGNB forms
cover images and provisional audio; the opaque bytes and typed tables above need
a raw/table extension if they are packed in AGNB. The examples do not promise
such a form already exists or invent its descriptor. No extra per-asset runtime
filenames or name-to-ID lookup is needed. Stock VDP cannot ask MOS to load files.

## Scope and safety level

Record/Table/Asset declarations, Bounds clauses, record construction, field
access, Array operations and their broader types are proposed syntax. The review
examples do not qualify them as current executable support. EX-018's selected
Array declaration and ordinary no-terminator syntax remain consistent with the
existing design. EX-022's comment now correctly distinguishes proposed signed
divmod from the implemented resident uint16 builtin.

Checks concern index validity and source-value admission, not post-copy byte
verification. Validate changing external inputs and reuse established validity
for internal operations while it remains true. Avoid repeated checks for trusted
resident data, host readbacks, checksums and rollback machinery. On a defined
failure, preserve the whole assignment destination and end the resident job;
earlier successful statements remain committed.

The proposed indexed-store order is left-hand indices once left to right, bounds
checks, then right-hand evaluation once and admission before commit. Numeric
status codes and backend support limits remain implementation details to review.
Float runtime admission and whole-record failure preservation still need their
own qualification before implementation is advertised.
