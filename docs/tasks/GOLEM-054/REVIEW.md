# Float32 output review

This review displays numbers formatted by Golem's resident buffered commands on
stock VDP. The C client installs the program, supplies each four-byte float input,
calls `Sub show`, and adds row breaks. It does not convert numbers to text.
The complete reviewed source is [review.golem](review.golem); deployment copies
it to `numbers.golem` on the emulated SD card.

The dedicated instance is actual Fab Agon Emulator 1.2.5 with MOS 3.0.2. It uses
a stock native VDP module. Flexe is not involved, and no hardware is flashed.

## Review on Oryx

```bash
cd ~/Agon/mystuff/golem/.emulator/golem-054
./fab-agon-emulator
```

The native Agon compiler compiles `numbers.golem`, then the client clears the
screen and prints fourteen rows. Golem uses nine significant decimal digits,
removes trailing fractional zeros, and selects ordinary or scientific notation.
For example, an input written as `0.1` produces `0.100000001`: this exposes the
stored binary32 value rather than pretending decimal 0.1 is exact.

The rows include positive and negative numbers, rounding ties, the ordinary/
scientific boundary, a large exact integer, and both finite float32 extremes.
The exact expected rows are retained in `deployment.json` beside this guide.
Follow the single onscreen keyboard instruction, close the emulator, and report
whether the text and keyboard worked. The agent retrieves the saved results;
there is no second terminal command for the reviewer.

## Automated checks

`qualify.py` compares two complete screenshots for every case: independent
oracle text printed by the test client, then the same text generated by Golem.
The reference scenes run only in automated qualification; they are not hidden
additional output in the human demonstration. The test also observes error
status and every source byte, then checks actual MOS keyboard continuation.

The finite target set contains 56 ordinary float cases plus eight inadmissible
bit patterns and eight succeeding zero calls. These exercise all-range extrema,
fixed/scientific boundaries, ties to even, decimal carries, stale sign/digits,
nonfinite/subnormal rejection, input preservation, and status reset. Relocated
buffer IDs receive a separate run. The broader independent decoder suite lives
in `check.py`; it is separate from these unchanged-stock-VDP observations.

The small one-global/one-Sub source is compiled by the actual eZ80 compiler and
its output is compared byte for byte with the host compiler's package. The
larger expression/control-flow fixture is checked separately by `check.py`.

```bash
.venv/bin/python docs/tasks/GOLEM-054/qualify.py
.venv/bin/python docs/tasks/GOLEM-054/qualify.py --relocated --host-package
.venv/bin/python docs/tasks/GOLEM-054/stage_oryx.py --qualify
.venv/bin/python docs/tasks/GOLEM-054/stage_oryx.py --review
```

These are agent qualification/staging commands, not required reviewer steps.
The Oryx stage is left stopped. Numerical and screenshot evidence does not claim
human acceptance. New implementation remains uncommitted pending that review
and explicit publication approval.

## Native compiler memory

The initial two-global example with a multiplication and two formatted values
ran out of native eZ80 compiler memory while building stock wrappers. It returned
a normal error to MOS; this is a compiler RAM limit, not a restriction on the
resident formatter or the VDP's float range. The exact source and diagnostic are
retained in `memory-limit-case.golem` and `memory-limit.png`.

The distribution therefore uses one initialized float and one formatted value:
`reading=1.5`. The actual MOS compiler produces all eleven package files exactly
as the host compiler does, and the unchanged distribution runner renders the
expected text pixel for pixel. This tranche does not change compiler allocation.
