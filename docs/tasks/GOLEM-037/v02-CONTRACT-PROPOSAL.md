# Concrete helper contract proposal — R25-RENDER v0.2

This proposal freezes a testable Rally C helper boundary while Golem owns the generated binding/glue. It supersedes the earlier opaque-signature proposal only after peer acceptance. The helper is isolated host work in the released TRF-001-23–26 tranche; it does not authorize combined linking, target runs, new recovery rules or pixel research. The exact proposed ABI is [rally_render.h](rally_render.h), with compile-time size/offset assertions and SDK-v1 buffer services only.

## Native call and ownership

Explicit caller-owned context replaces hidden singleton state. Bind/prepare take host, context, typed bindings/state and completion; stop takes context/completion. Context is84 bytes; bindings76; state108 including six12-byte opponents; completion48. These are native C structures, not packed MOS/UART packets. Scalar widths and field order are fixed by the header. No pointer or lease persists in context. Host/context/state/completion storage must be valid, mutually nonoverlapping native objects for the whole call; generated glue must copy snapshots and not point into mutable receiver storage. Helper preflight also rejects writable retained ranges aliasing its native objects or immutable asset range.

Bindings contain generated asset and three output buffer ranges (ID/access/offset/bytes), nonzero session, canonical track/checksum identity and resource IDs for player/opponent/sign bitmaps/matrices. Assets use READ, outputs WRITE. Bitmap and matrix ranges must be legal and disjoint within their resource namespaces. No production numeric IDs are assigned; old fixture IDs remain test inputs only. The root-role4 directory can construct these typed bindings but its packed installation encoding is outside this C ABI. Root-v1 is unchanged.

The renderer uses the frozen two-track asset blobs and ordinary VDU lists. Bind rejects changed checksum/shape/identity or conflicting ranges and invalidates any prior binding on failure. Success retains a copy of descriptors/identity only. Allocations/assets/resource identities stay immutable until stop/rebind while quiescent. Prepare validates state, reacquires asset and outputs, emits road/actors/player lists, terminates all outputs and publishes completion last. State's request_generation/simulation_tick are opaque uint32 metadata (zero/wrap permitted); session must match. No sparse reconstruction or independent duplicate policy is introduced. Normal presentation requires reference counters zero; profile1 exists solely to replay historical R24 crash/invulnerability fixtures and does not freeze new gameplay recovery. New effect policy requires an explicitly reviewed extension.

## Failure and completion

Return value is an SDK-compatible int32 result:0 success; argument/state errors1; capacity/range errors3; bad canonical assets4; ABI5; not-bound12. Actual acquire/release failures propagate the exact nonzero SDK callback result. Completion.result matches return; reason is the independent small helper category in the header, and service_result carries callback failure when applicable. These never become Golem arithmetic language status. Valid completion storage is cleared at entry; invalid completion shape returns argument error without unsafe writes. Outputs/earlier source effects can already have changed; no rollback is promised.

Ready is0 for bind/stop/failure and becomes1 only after all command lists and successful view releases. Successful prepare carries matched session/request/simulation tick, all three lengths and bands/cars/signs. Invocation owner must clear readiness before attempting RUN, including failures before helper entry, then require runtime/interface/language/helper results plus fresh root successful-generation and matched completion before drawing. Failure returns from generated wrapper before the root-success suffix, preserving preceding source effects and previous root success markers. Stop invalidates helper context; firmware must separately drain invocation/drawing before calling it/unloading. No implicit draw or scheduler exists in this helper.

Root argument is copied/resolved and its lease released before helper entry. The intended combined peak is root+asset+one output=3. Preflight visits output ranges sequentially; generation also leases one writable output at a time. No second module/recursive loader/cached views. Any release failure leaves ready0 and reports failure; caller/runtime must resolve a failed lease release before continuing, even if helper cannot free it. One drawing owner consumes completed output before reuse.

## Proposed compiler/build binding spelling

Prefer a bounded build-level binding profile without general pointer/function language features: `--native-bindings PATH`, JSON schema1/profile `rally-render-v1`, with hooks keyed by source Sub name. InitRace/ResetRace map to bind, Render30 to prepare, StopRace to stop; hook phase is `after_source_before_success`. A normal parameterless Sub remains shared source. Requiring this profile causes explicit compile rejection on buffered target; it must not silently compile a no-render path. Exact source field/array maps are by declared names and generated layout metadata, never private offsets.

Generated `interface.native_bindings` publishes profile/schema, source entries, C symbol/signature/header hash, required capability1, input/global/array names, context ownership and completion location. Bindings/state/completion are generated native locals/private context and named application-owned completion storage as declared; initialized values/resource IDs come from generated installation bindings. Root completion record may be source globals or a generated application extension after ordinary globals, with its manifest length/offset explicit; do not repurpose root header fields or collision mailbox. This profile is a proposal for Golem to accept/amend before shared integration, not a claim current compiler supports the flag.

Requested acceptance: exact header ABI/functions, SDK-compatible helper error propagation and separate completion, build-level hook spelling/marshaling declaration, early failure before root success, early argument release and native-only rejection. The extracted helper may be host-tested against this explicitly proposed header while that discussion proceeds. Concrete renderer implementation remains Rally-owned; compiler binding/glue remains Golem-owned. Physical/resource/cadence evidence belongs to later composition.
