# Concrete helper contract revision — R25-RENDER v0.3

The current proposed ABI is [rally_render.h](rally_render.h); the original v0.2 header/proposal are preserved under [proposals/v02](proposals/v02/CONTRACT.md) with their mailed hashes. This revision changes native private context storage and accepts Golem's separate completion-buffer refinement. Binding names/state/completion/error behavior remain as proposed except the explicit clarifications below. It is pending peer acceptance; host implementation is exercised independently without claiming generated compiler integration.

## Context and lifetime refinement

Context is now **464 bytes**: header/bindings84, typed snapshot108, eight28-byte actor scratch records and two six-element int32 ordering/depth arrays. Header asserts size and snapshot offset84. All context members are values; no pointer/lease is retained. Preparation copies the input snapshot into context and uses its private per-context scratch. This preserves isolated/interleaved contexts while moving large transient arrays off the call stack. Bindings76, state108, opponent12 and completion48 (ready offset44) are unchanged; bind/prepare/stop function signatures are unchanged from v0.2. Header layout is native C, not UART/MOS bytes. Generated glue allocates/initializes the correct context size from this revision.

The original ordinary host compiler report placed1008 bytes in the prepare frame. That is not an ESP32 stack measurement, but justifies the storage change before acceptance. Current host frames are recorded as diagnostics only; target/composed stack including callbacks and generated glue remains a later admission requirement. Context/private data similarly counts toward eventual module resources. No stack or capacity limit is changed/probed here.

## Completion storage refinement

Accept Golem delivery-seven's separate generated **application-owned48-byte completion buffer**, represented by ID/offset/length/ownership in `interface.native_bindings`. Root-v1/global-byte semantics remain unchanged; no non-source root footer or collision-role reuse. The C helper takes a caller-owned native completion local. After all helper views are released, glue publishes that record to the retained completion range, using root+completion at that point. Root+asset+output peak3 assumes the argument view was copied/released before helper entry.

Local helper ready1 means all helper output lists and their view releases succeeded. Completion-buffer acquisition/copy/release is a distinct operation that can fail afterward. Any such failure must return nonzero SDK status and skip root-success publication. Resident ready alone cannot authorize drawing, including when a publication release fails after ready was written. The draw gate requires observed runtime/interface/language/helper success, matching session/request/tick AND fresh successful root generation. Invocation owner clears resident readiness before attempted RUN so pre-entry errors cannot reuse old output. No atomic transaction or rollback is promised. Manifest-generated handle patch offsets may change when ready-clearing wrapper bytes are added.

Completion result follows the helper return, with distinct helper reason and callback service result. Argument/state failures return SDK1; actual capacity/range failure3; canonical asset/shape failure4; ABI5; not-bound12; acquire/release propagate their actual SDK nonzero codes. Descriptor syntax/overflow/access/resource-validation failures are argument1, distinct from a callback's actual range3. Language arithmetic codes never represent these failures. Failure prevents the generated root-success suffix. Malformed native object/size/alias preconditions may return argument error without writes; only safely admitted completion storage is cleared. Bind invalidates earlier binding after safe argument admission, including later asset/service failure. Release failure during prepare also invalidates context; an unfreed lease requires runtime entry cleanup before proceeding.

## Compiler/build agreement requested

The bounded proposal remains `--native-bindings PATH`, JSON schema1/profile `rally-render-v1`, hooks by named Sub with `after_source_before_success`: InitRace/ResetRace→bind, Render30→prepare, StopRace→stop. Native-only requirement rejects buffered compilation explicitly. `interface.native_bindings` identifies the C header/signature, capability1, named source globals/arrays, context ownership/size, generated typed bindings/state maps and retained completion descriptor. No private offsets/production IDs are assumed. Generated glue performs argument release, typed marshaling, distinct helper-result publication and early return before root success. This is a proposed compiler spelling, not an implemented flag.

Normal presentation has zero legacy effect counters. Profile1 only replays old R24 fixture presentation; it does not determine the new countdown/explosion/reintroduction policy. Resource IDs and bounded retained ranges are generated bindings; allocation/asset identities remain immutable while bound, and one owner serializes calls/drawing. Concrete combined linking, target stack/resource admission, firmware/timing/recovery decisions and the Author's final visual confirmation remain later gates. No further pixel research is part of this tranche.
